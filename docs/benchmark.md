# Organization benchmark

This baseline was shaped by public organizations that are mature in areas
adjacent to Mylabella's work. The comparison focused on information
architecture, contributor routing, and governance proportionality.

No third-party repository was copied wholesale. Mylabella's policies are
original and deliberately smaller than the processes used by large foundations.
The standard Contributor Covenant is the exception and carries its own
attribution and license in `CODE_OF_CONDUCT.md`.

## Benchmarks

| Organization | Relevant practice | Adaptation for Mylabella |
| --- | --- | --- |
| [farmOS](https://github.com/farmOS/.github) | Makes non-code participation explicit and routes questions away from bug tracking | Contribution types and support routing are separated |
| [FreeCAD](https://github.com/FreeCAD/.GitHub) | Uses the organization profile as a navigable project map | The profile lists only public, ready-to-use projects and their maturity |
| [Home Assistant](https://github.com/home-assistant/.github) | Leads with a concise outcome and clear local-control principles | The profile states a practical mission and local-first design direction |
| [Model Context Protocol](https://github.com/modelcontextprotocol/.github) | Connects mission, project structure, contribution, and security entry points | The profile and defaults form one route from discovery to contribution |
| [Nextcloud](https://github.com/nextcloud/.github) | Separates product help, enterprise support, defects, and security reports | Support, defects, proposals, conduct, and security use distinct paths |

## Practices intentionally not adopted

- Committees, voting bodies, and formal working groups: Mylabella does not
  currently have the maintainer population to operate them honestly.
- Guaranteed response times: public experimental projects cannot promise an
  unsupported service level.
- Organization-specific labels or assignees in default issue forms: inherited
  forms must work in repositories with different label and team configurations.
- Detailed public roadmaps for unpublished work: the public profile describes
  capabilities without exposing private repositories or internal plans.
- Default repository licenses: GitHub does not inherit a `LICENSE` from the
  organization `.github` repository.
